# 需求草案与采访

状态：待用户确认，不是已批准的实现规格。

## 已明确的目标

研究《英雄联盟》海克斯大乱斗“大法师”，构建直观、清晰、有高级感的中文网页：

1. 获取真实英雄的技能信息、逐技能等级 CD 和加点规则。
2. 搜索英雄，发现可以交替互刷的技能对。
3. 找出合适的技能等级搭配，并说明应如何控制加点。
4. 展示成型所需冷却条件，让用户理解原因而不只是看到榜单。

用户提供的机制描述：施放技能，将当前技能原始 CD 的 30% 返还给另一个技能。

已由用户确认：“原始 CD”指施放技能在当前技能等级下、未经技能急速缩减的基础 CD。例如基础 CD 为 10 秒，即使急速后实际 CD 为 3 秒，施放它仍给另一技能返还 3 秒。此定义不等同于剩余 CD，也不是被返还技能的基础 CD。

已由用户实测确认：只使用 A/B 两个技能交替施放时，大法师必定返还另一个技能的 CD。因此本项目的两技能交替模型可以采用确定性互相返还，不需要在该场景下引入随机命中概率。证据类型为用户实测口述，尚未附录像或对局版本。

该结论不自动外推至三个及以上技能参与、其他技能也处于冷却等场景。

## 已确认的加点输出范围

- 只需给出最优技能等级搭配，例如 `Q3 / E1`。
- 不需要指定英雄等级，不需要逐级加点路线，也不以最早成型等级为优化目标。
- 仍需遵守技能本身允许的等级范围；不将旧项目宽松的点数检查当成完整加点规则。

- 并列判断基于内部精确计算与合理数值容差，不能只比较显示时四舍五入后的数字。

- 对交互暂未确认的多段施放、变形等特殊技能，可标注“待核验”并暂不参与最优排名。

- 用户已确认：充能技能以恢复一层充能所需的时间作为普通 CD 模型的输入，不采用连续使用两层之间的短暂施放间隔。此为首版约定，并不代表已经实测验证充能类的全部交互。

## 已确认的首要优化目标

用户确认：只要满足 A/B 无限循环互刷，所需技能急速最低就是最优解。技能等级组合的优化应以最低成型急速为第一目标，不以循环最快或成型等级最早代替此目标。

用户已确认首版采用“无等待互刷”的保守门槛：忽略施法动作耗时及期间的自然冷却，要求单次返还足以清空另一技能的完整实际 CD。不进行操作节奏或施法时间仿真。

对于两技能共用技能急速 H 的普通模型，设当前技能等级下的基础 CD 为 C_A、C_B，返还比例 k=0.3，则：

```text
C_A / (1 + H/100) ≤ k × C_B
C_B / (1 + H/100) ≤ k × C_A
H_min = max(0, 100 × max(C_A/(k × C_B) - 1,
                         C_B/(k × C_A) - 1))
```

该公式用于已确认的首版模型，不表述为所有实战循环的必要门槛。充能类以恢复一层所需的基础时间代入，并保留估算标注。

以下指标可以作为解释或未来的次级排序，但尚未确定同门槛时如何取舍：

“需要的 CD 最短”可能指不同目标，不能直接混为一个排序：

- **最低成型急速**：通过匹配基础 CD，降低互刷所需技能急速。
- **最快循环**：在指定急速和施法限制下，缩短重复循环耗时。
- **最早成型等级**：在合法加点条件下，尽早达到互刷组合。

旧项目优化第一项，符合已确认的首要目标；它在同门槛时偏好技能等级总和更高，这个次级取舍尚未经本轮需求确认。

## 采访顺序

每轮只问少量高价值问题，根据回答更新本文，不一次性抛出长问卷。

### 第一轮：机制可信度与返还目标

- 30% 基数、目标选择规则，有无本人实测、截图或可复现场景？
- 当只交替按 A/B 而另外技能就绪时，返还是否还会命中另外技能？
- 其他技能进入冷却时是否分流？
- “原始 CD”是当前技能等级、急速前的基础 CD，还是其他定义？

### 第二轮：成功标准

- 最优首先指最低成型急速、最快循环，还是最早等级？
- “互刷”是否要求每次施法立即刷新另一技能，还是允许极短等待？
- 用于个人研究、对局选人时快速查询，还是公开网站？

### 第三轮：范围与约束

- 是否包含 R、变形技能、充能、多段和条件重置？
- 是否考虑装备、其他海克斯、独立技能急速、资源消耗？
- 全英雄覆盖与首版准确性如何取舍？
- 指定英雄等级、保留技能点、不学习其他技能等策略是否允许？

### 第四轮：数据与体验

- 国服模式与版本口径；更新方式与人工纠错需求。
- 网页视觉参考、主要设备、搜索习惯。
- 已明确希望 GitHub Pages 部署、手机和电脑访问；分享计算方案需求尚未确认。
