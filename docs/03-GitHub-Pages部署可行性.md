# GitHub Pages 部署可行性

核验日期：2026-10-31。

## 结论

适合本项目：采用纯静态前端，发布前抓取并规范化版本化 JSON 数据，浏览器负责展示、搜索和计算，不需要常驻后端。此为设计建议，尚未开始实现、创建远端仓库或公开发布。

## 官方文档核验与待核验项

- GitHub Pages 托管 HTML/CSS/JavaScript 静态内容，支持构建后发布；GitHub Free 可用于公开仓库。
- 本轮浏览工具未返回内容，随后通过命令行成功读取 GitHub 官方说明并确认上述托管类型和免费公开仓库条件。
- Riot 文档通过命令行访问也遇到 TLS 错误。本轮未核实图标资源路径、技能说明字段、版本更新行为或发布政策；正式采集和发布前必须核验。
- 数据方案拟采用 Data Dragon/Community Dragon；技能图标、说明与模式数据的完整性需用真实样本验证。不将数据源“最新版”直接当作国服海克斯大乱斗的准确版本。
- 正式公开前核对 Riot 素材使用、产品注册和非官方声明等适用政策，不将素材可获取视为无限制使用授权。

## 建议的数据流

```text
按明确版本获取数据
  → 字段校验、异常清单、模式差异核验
  → 生成规范化 JSON 和图标资源清单
  → 构建静态网页
  → 发布到 GitHub Pages
  → 手机/电脑浏览器搜索、展示与计算
```

网站访问时不依赖临时抓取，不向前端放 API 密钥。构建或维护任务更新数据，不能在 Pages 服务端运行 Python 抓取器。

图标可考虑作为版本化静态资源随站点发布，降低对外部图片站点即时可用性的依赖；具体取用和缓存需遵守资源政策。不承诺 GitHub Pages 在所有地区、网络中始终可访问。

## 首版展示建议

- 英雄列表：英雄图标、名称、最优技能对和最低技能急速。
- 搜索：按英雄名即时筛选。
- 英雄详情：技能图标、中文说明、逐技能等级基础 CD。
- 最优解：并列最优加点、精确急速门槛、需要整数时向上取整的建议值。
- 解释：急速后的实际 CD、两方向的返还秒数，以及为何满足互刷条件。
- 页脚或显著说明区：数据版本、更新时间、模型假设、特殊技能标注、非官方声明。
- 移动端不依赖鼠标悬停查看技能说明，使用点击展开等交互。

## 待确认

- 已确认首版不自动检查版本、不自动更新数据；采用版本化快照，后续手动发起更新，不添加定时更新工作流。
- 英雄搜索是否扩展到常用别名、拼音？
- 视觉风格与分享方案需求。
