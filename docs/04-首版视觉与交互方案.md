# 首版视觉与交互方案

状态：助手设计建议，尚未实现。用户已授权由助手设计，无外部风格参考。

## 定位

工作名：**大法师 · 互刷研究所**。

做一个有游戏气质的精密研究工具，而不是宣传落地页。优先保证找英雄、看加点、理解急速门槛的速度。

## 视觉

- 深墨蓝背景、分层深色面板、低饱和香槟金强调；青绿色用于返还关系和计算说明。
- 避免大面积渐变、霓虹、装饰光效、巨大宣传标题和无用动效。
- 英雄图标与技能图标是识别主角；技能等级用 `Q3 + E1` 等清晰标签。
- 急速与 CD 数值使用等宽数字，单位和说明不抢主数值层级。
- 使用系统中文字体，避免为首屏引入额外远程字体依赖。
- 搜索、焦点、选中、待核验等状态同时使用文字或边框表达，不只靠颜色。

## 页面结构

### 1. 紧凑顶栏

工作名、版本快照、计算模型入口。手机端保持简洁，不占用过多可视区域。

### 2. 英雄发现

- 搜索放在明显位置，支持按英雄名即时筛选。
- 列表展示英雄头像、名称、最低技能急速和最优技能对。
- 以所需急速升序呈现，视觉上不把同门槛的英雄暗示成实力排名。
- 空结果给出明确提示，保留清空搜索入口。

### 3. 英雄详情

- 电脑：英雄列表与详情并排，便于比较和切换。
- 手机：选择英雄后查看单列详情，有明确返回列表入口；不把桌面多列表格硬压缩。
- 先显示最优技能对、最低技能急速、全部并列最优加点。
- 再按技能对展示其他候选解，避免只显示全英雄最低的一对而隐藏有研究价值的组合。
- 许多并列组合可以折叠，但必须标明数量、可展开全部，不静默截断。

### 4. 技能与解释

- 每个技能显示图标、名称、中文说明、逐级基础 CD；手机点击展开，不依赖悬停。
- 明确区分：基础 CD、急速后的实际 CD、施放时返还给另一技能的秒数。
- 双向解释：A → B 与 B → A，各自展示实际冷却与返还的比较。
- 精确阈值与整数建议值分开。例如理论门槛 `233⅓`，整数急速至少 `234`；不使用四舍五入后的 `233` 作为成型门槛。
- 充能类显示“以恢复一层时间代入普通 CD 模型，实际交互待核验”。
- 缺失数据与不适用不能显示为 0 急速，也不伪装成已验证结果。

### 5. 模型说明

统一说明：返还基数为当前技能等级的基础 CD 的 30%；只交替使用两个技能；包含 R；忽略施法耗时和自然冷却；只比较最低所需技能急速。

展示来源、版本与更新时间。素材政策与非官方声明在正式公开前核验落实。

## 不做

- 不做账号、登录、后台、出装推荐、自动版本更新。
- 不做逐级加点路线或指定英雄等级筛选。
- 不做依赖网络实时抓取才能打开的页面。
- 不做尚未核验的实战强度、胜率或“最强英雄”结论。

## 验收方向

- 手机和电脑都能完成搜索、查看技能说明、展开并列加点与理解计算依据。
- 320、768、1024、1440 CSS 像素宽度检查布局，无整页横向溢出。
- 键盘可搜索、切换英雄与展开说明；焦点清晰。
- 真实中文技能说明的长文本、图标加载失败、缺失数据与无结果均有明确呈现。
- 对精度边界进行计算测试，不能因显示舍入把未达门槛的急速标为成型。
