# 充能循环修正与公开发布（2026-10-31）

本文件覆盖早期规格中“单层近似”“不限制 500”“尚未授权发布”等旧约定。

## 用户确认

- 船长多层返还已实测；其他充能技能仅理论外推。
- 单个充能技能每轮可连续施放 n 次，累计返还普通技能 CD。
- 按当前技能等级的充能容量计算；不可把所有等级都当作 5 层。
- 优化目标仍为最低技能急速，完整保留并列最优加点。
- 超过 500 急速的结果完全隐藏；500 本身保留。不按显示精度截断。
- 授权使用 GitHub CLI 新建公开仓库、推送并部署 Pages。

## 数学与数据

参见 README 的单充能模型。每轮必须补回相同数量的充能且刷新普通技能；两个不等式同时成立。引擎枚举本等级容量内的整数施放次数，保留并列最优次数。普通技能视为一次。

双充能技能对暂不排名。有界批次枚举不能保证任意交织施放下的全局最优，不能把可行上界标为精确最低值。

18 个充能技能已重新读取锁定的 Community Dragon 16.21 客户端 JSON 的 `ammo.ammoRechargeTime` 和 `ammo.maxAmmo`。数组从技能 1 级开始，按 Data Dragon 的 maxrank 截取；保留来源在 `data/charge-verified-16.21.1.json`。重新生成网站数据不会自动联网刷新该文件。没有跨版本拼接，也未将内部 ammo 当作可储存充能。

船长 E 容量 3/3/4/4/5；单层回复 17/16/15/14/13 秒。ER 最好 E5×5 / R3，最低约 515.384615 急速，因此隐藏。寒冰 E4/R3 的一对一门槛为 233⅓。

筛选后默认 150 位英雄可显示，原始数据仍完整保留 173 位。手动等级选择器仅提供上限内的搭配；改变 A 等级时若旧 B 等级不合格，则选用该 A 等级的最佳合格 B，不展示超上限数值。

## 发布边界

仅发布本项目已跟踪源码、图标和固定快照。不发布 ZIP、旧程序、证书、缓存、node_modules 或测试产物；构建只收录站点白名单文件。

按 GitHub 官方 Pages REST 文档，创建站点使用 `build_type=workflow`，发布工作流为 `workflow_dispatch`，没有定时任务或推送自动更新数据。

已阅读 Riot Developer Portal 的 General Policies。页面附显眼非官方声明及官方建议的英文声明；站点所有者仍需处理 Developer Portal 产品登记/审核。本项目未代登录、未申请 API key，不声称已获 Riot 批准。
