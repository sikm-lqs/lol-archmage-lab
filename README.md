# 大法师 · 互刷研究所

海克斯大乱斗“大法师”技能冷却研究工具。搜索英雄、查看中文技能与图标、比较所有技能对，计算无限互刷所需的最低技能急速及所有并列最优加点。

**非官方、理论工具，不操作游戏客户端。固定快照工具；发布通过手动 GitHub Actions 完成。**

- 网站：https://sikm-lqs.github.io/lol-archmage-lab/
- 仓库：https://github.com/sikm-lqs/lol-archmage-lab

## 本地使用

需要 Node.js 22 或以上版本。网页运行和构建没有第三方依赖。

```bash
npm run dev
# 浏览器打开终端输出的本地地址，默认端口 5173

npm test
npm run build
npm run preview -- --port 5180
```

不要直接双击 `index.html`，浏览器可能阻止加载本地 JSON。

## 功能

- 收录 173 个英雄快照；仅展示至少一组所需急速 ≤ 500 的英雄（当前默认筛选 150 位），可按中文名、称号或英文 ID 搜索。
- 本地英雄及技能图标、中文基础说明、逐等级 CD。
- Q/W/E/R 全技能对比较；全部并列最优加点，不擅自偏好高等级组合。
- 自选两个技能等级，即时查看门槛与双向返还解释。
- 显示理论急速门槛与向上取整的整数急速建议。
- 充能按逐级容量枚举连续施放次数；标注理论外推，特殊交互、缺失数据显式排除。
- 桌面和手机布局，键盘搜索快捷键 `/`。
- 固定版本快照，无自动更新、账号、追踪或出装推荐。

## 模型

根据需求方实测，只交替施放 A/B 时，返还一定命中另一技能。返还量为施放技能当前等级、急速缩减前基础 CD 的 30%。

```text
实际 CD = 基础 CD / (1 + H/100)
H_min = max(0, 100 × max(C_A/(0.3 × C_B) − 1,
                         C_B/(0.3 × C_A) − 1))
```

普通技能模型要求单次返还足以清空对方完整实际 CD，忽略施法时间、自然冷却、目标要求与资源消耗。包含 R，但不计算独立大招急速或其他特殊急速来源。基础 CD 相同时门槛为 `233⅓`，整数急速需至少 `234`。

### 单充能技能 + 普通技能

C 为单层基础回复时间，R 为普通技能基础 CD，N 为当前等级充能容量。枚举 `n = 1…N`，每轮 `R → C × n → R`：

```text
H(n) = 100 × max(n*C/(0.3*R)-1, R/(n*0.3*C)-1)
```

两个方向分别保证 R 补回本轮消耗的 n 层、n 次 C 刷新 R，取最低门槛。返还溢出不突破容量，不把初始存量误认为可永久循环。双充能技能对暂不排名：仅枚举两个有界批次不足以保证全局最优。

- 船长 E 容量 `[3,3,4,4,5]`，回复 `[17,16,15,14,13]`；R `[160,140,120]`。最佳 ER 是 E5×5 / R3，需要约 **515.384615** 急速，所以按上限隐藏。
- 寒冰 E4/R3 都是 60 秒，可一对一循环，门槛 **233⅓**。
- 只展示所需急速 **≤500** 的技能对、等级搭配及英雄。内部精度判断，不按显示四舍五入放行。
- 船长多层返还机制由需求方实测；其他充能英雄按同机制外推，不声称已实测。

## 数据与准确性边界

- 版本锁定为 **16.21.1**。普通 CD、中文说明、图标重新采集自 Riot Data Dragon。
- 18 个充能技能的单层回复时间和逐等级容量已重新从 Community Dragon 16.21 客户端数据采集，保存在 `data/charge-verified-16.21.1.json`（含逐项来源与采集日期）；旧快照仅保留识别来源，不代替本次核验。
- 旧数据中一些内部 ammo 字段并非玩家可储存充能，已针对已识别槽位排除该误判。
- 部分形态、重施放、条件重置和属性影响技能暂不参与排名；人工例外清单不保证穷尽所有情况。
- Data Dragon 基础技能数据不保证覆盖海克斯大乱斗的全部模式修正。**数据真实来源不等于所有模式交互已验证。**
- 技能说明为基础描述，不一定包含完整动态伤害数值；本项目核心关注技能冷却。

### 手动更新同版本快照

```bash
python3 scripts/fetch_data.py
npm test
npm run build
```

采集器使用 `.cache/16.21.1/` 原始 JSON 缓存；没有定时任务，不追踪 `latest`。更换版本时需显式修改采集版本，并重新核验充能来源与例外，不能混用版本。`public/data/champions.json` 和 `public/assets/` 必须纳入版本管理，保证克隆后无需联网抓取即可构建。

## GitHub Pages 部署

已获需求方授权创建公开仓库并部署。首次和后续发布都使用手动工作流。

1. 首次已使用 GitHub CLI 创建公开仓库并推送 `main`。后续修改后先提交并 `git push`。
2. 在仓库 Settings → Pages 中将 Source 设为 **GitHub Actions**。
3. 在 Actions → **Deploy Archmage Lab** → **Run workflow**，选择 `main` 并运行；或执行 `gh workflow run pages.yml`。
4. 成功后通过部署结果给出的地址访问，手机和电脑使用同一地址。

工作流只由手动按钮触发，不定时更新数据，也不在每次推送时自动发布。`dist/` 是唯一发布目录；ZIP、旧程序、证书、原始缓存和测试截图不会进入站点。

项目使用相对路径，兼容 GitHub Pages 的仓库子路径。网站已包含非官方声明；Riot Developer Portal 的产品登记与审核须由站点所有者处理，本项目不声称已获 Riot 审核或认可。当前未替用户选择代码开源许可证；游戏素材不属于本项目代码的授权范围。
